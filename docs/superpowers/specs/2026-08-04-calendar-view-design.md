# 日历视图设计 · 周视图 + 月视图

2026-08-04

## 背景

五视图承诺了列表 / 日历 / 地图 / 预算 / 资料，目前落地三个。日历是唯一能兑现
「让时间的形状看得见」这句话的地方 —— 列表**刻意**放弃了按时长的比例高度
（`lib/layout.ts` 开头写明：没有轴就读不出比例，那是日历的活）。

参考 Apple Calendar 的周视图与月视图。**不做日视图**。

## 三级下钻

| 视图 | 回答什么 | 不回答什么 |
|---|---|---|
| 月 | 这趟旅行的结构：哪几天在哪、哪天换酒店、哪天满哪天松 | 具体几点 |
| 周 | 每件事占多长时间、一天里有多少时间在路上、哪里有大空档 | 细节内容 |
| 列表 | 这件事是什么、有什么坑、怎么订 | 时间的形状 |

点月格子 → 周视图定位到那天；点周视图的方块 → 列表对应卡片（列表卡片已有
`id={event.id}` 锚点和 `scroll-mt`，现成的）。

## 一、位置与导航

顶栏加第二个标签：`列表 | 日历 | 资料 | 预算`，路由 `/trip/:id/calendar`。
日历内部一个 `周 / 月` 分段开关，复用筛选栏 `简/详` 的样式，选择存
`localStorage` 键 `jjj:calmode`。

## 二、周视图

### 列模型：行程周

把行程的天并排，一屏放下；超过 7 天按**行程顺序**分页（第 1–7 天 / 第 8–14 天），
不按自然周边界切。列头写 `Day 1 · 10/01 周四`，星期信息不丢。

> 为什么不用 Apple 的固定周一–周日：西雅图 10/01（周四）–10/05（周一）会被切成
> 两页，第一页 4 格空、第二页 6 格空，一半屏幕是死的。

### 时间轴

- **范围自适应**：取当前页所有天的最早 `startMin` / 最晚 `endMin`，向整点外扩。
  西雅图算出来是 07:00–23:00。设 **8 小时下限**，免得事件少的一天把轴压扁。
- **56px/小时**，视图内纵向滚动。
- 跨午夜（`endMin > 1440`）：方块钳到轴底并标记，不把轴拉长到 48 小时。

### 四类事件各有画法

| 类型 | 画法 | 理由 |
|---|---|---|
| `exact` | 按时长的方块：5% 族色底 + 左色条，与列表卡同一视觉族 | 高度=时长，这是周视图存在的理由 |
| `point`（时长 0） | 18px 高的细标记，只有左色条、不填充 | 它没有占用时长，填成方块就是撒谎 |
| `period`（上午/下午） | **斜纹块**铺在名义窗口上 | `packages/schema/src/time.ts` 早就写明「UI 必须用斜纹块区分」，这次兑现 |
| `allday` | 轴上方单独一条全天带 | 否则一个全天事件糊满整列（`_demo` Day 2 的周游券就是） |

### 通勤按真实时长画

灰色、内缩、比事件窄一档。西雅图 29 段带时长的通勤会让轴显示「这天有多少时间在路上」
—— 这正是列表答不了的问题。

附带好处：某段通勤长过空档时（解析器警告的那种冲突），方块会**真的压到下一个事件上**，
冲突肉眼可见。两个事件本身重叠时（`layout.ts` 新加的 `overlapMin`）同理。

### 其它

- **今天的红线**：当天落在行程区间内才画。
- **手机**：列最小 88px + 横向滚动，左侧时间轴 sticky。5 天在 390px 上放不下文字，
  但色块的形状还在，「哪天满」照样一眼看出。

## 三、月视图

### 网格

周一起始的 7 列。**包含行程的那几周全亮，前后各多渲染一周并渐隐**
（透明度梯度 + 行高压缩），保留「这趟旅行落在这个月哪个位置」的空间感，
又不出现 80% 空格子。

### 格子内容（自上而下）

1. **日期数字** —— 行程日加粗放大，今天加圆点
2. **住宿区间条** —— 横跨多格的细条，换酒店那天自然断开。多城市行程里
   「人在哪」是最强的宏观信号
3. **当天主题** —— 截断一到两行；不可移动的锚点（航班/入住/退房）用小图标压在行尾
4. **密度条** —— 玩/吃/其他占比，与首页卡片、左侧日程轨同一套语言

## 四、随行的架构收敛

加视图之前必须收敛，否则日历就是这些重复的下一份。**每一条都是日历真会用到的能力。**

| # | 现状 | 日历用在哪 | 怎么改 |
|---|---|---|---|
| ① | MM/DD 短日期 **6 处各写各的**，其中 `lib/time.ts:22` 的 `shortDate` 导出了但**全仓零调用**（还用 `.` 分隔符） | 周表头、月格子日期 | 统一到 `lib/format.ts`，删掉其余 5 处 |
| ② | 加减天数 / 天数差：`@jjj/tripmd` 已导出 `addDays`/`daysBetween`，但 `derive.ts:60`、`transport-dates.ts:43`、`ics.ts:60,67` 各手搓一遍 | 月网格填充、渐隐周边界 | 全部改用 `@jjj/tripmd` 的实现 |
| ③ | 时长格式化 3 处、2 种输出：`serialize.ts:55` 与 `TransportTimeline.tsx:353` **输出完全相同却各写一遍**，`DayTimeline.tsx:670` 是中文版 | 事件时长标注 | `lib/format.ts` 导出 `fmtDurationZh` / `fmtDurationCompact` |
| ④ | 「当天玩/吃/其他构成」：`summary.ts:11` 的 `dayShapeOf` **模块私有没导出**，`DayRail.tsx:100` 因为拿不到而照抄了同一条公式（连 `Math.max(时长,15)` 的名义值都一样） | 月格子密度条 | 从 `@jjj/tripmd` 导出 `dayComposition(day)`，两处消费 |
| ⑤ | `BudgetView.tsx:12` 为拿一个 `fmtMoney` import 了 651 行的 `DayTimeline` | 日历要显示费用时会复制这个模式 | 随 ③ 一起挪进 `lib/format.ts` |

> ① 的证据值得记一笔：「写了共享函数但没人知道、各自重写」在这个仓库**已经发生过一次**
> —— 不是假设。
>
> ② 里有一条是我自己刚造的：`transport-dates.ts` 的 `plusDays` 与 `@jjj/tripmd` 的
> `addDays` 完全等价。一并收掉。

### 目录归属规则（新建 `features/calendar/` 从一开始就遵守）

`components/` 只放 **2 个以上视图共用**的东西；只有单一视图用的放 `features/<视图>/`。

实测现状：`Markdown`(3 视图)、`RailLayout`(2)、`States`(3)、`CategoryChip`(2)、
`ticket-parts`(2) 是真共享；而 `DayTimeline`、`TransportTimeline`、`DayRail`
**只有列表在用** —— 解开 ⑤ 之后它们可以搬进 `features/itinerary/`。

**不改** `features/itinerary`↔`list`、`features/reference`↔`info` 的历史命名不一致
（纯改名，收益低于风险），但日历不做第三种先例。

## 五、代码结构

```
apps/web/src/lib/
  calendar-grid.ts     纯计算：月网格（含渐隐周）、区间跨行裁剪、住宿跨格
  week-axis.ts         纯计算：轴范围、方块定位、租车底色带
  lanes.ts             泳道贪心（月视图区间带 + 周视图重叠分栏共用）
  *.test.ts            各自单测，跟着 pnpm test 跑
  format.ts            新：MM/DD、时长、金额（收敛 ①③⑤）
apps/web/src/features/calendar/
  CalendarView.tsx     壳 + 周/月开关
  WeekGrid.tsx         周视图
  MonthGrid.tsx        月视图
```

所有布局数学放纯函数、组件只管画 —— 与 `lib/layout.ts`（列表行编排）同一套分工。
轴范围、跨午夜、渐隐周边界这些容易错的地方靠测试钉住。

数据一律来自已解析的 `Trip`，**不碰 TripMD 格式，不新增任何字段**。

> `lib/layout.ts` 的文档字符串本身就是「列表不按比例布局」的设计结论，
> 日历的比例布局**另开 `calendar.ts`**，不塞进去自相矛盾。

## 实现记录（2026-08-05 落地）

设计到实现之间改了八处，都是动手后才暴露的问题，记在这里免得下次重新踩。

**1. 住宿升格为一等区间。** 设计只说「不碰 TripMD 格式」，但月视图要按真实时刻
画区间带时发现住宿根本没有时刻：名字散在 `day.lodging`（每天重复一遍）、
字段挂在 `event.stay`、区间靠 `buildStaySpans` 用**字符串相等**合并出来。
往上补两个字段只是在歪地基上加第四处。改成顶层 ` ```trip-stays ` 块，与
` ```trip-rentals ` 共用 `ReservationBase`。净删代码，还从根上消掉了 code review
的 F3（名字大小写一漂区间就断）。

**2. 保底时刻在解析时填、不在消费方填。** 原计划怕填了会破坏往返幂等。
实际上 `serialize` 写回的是作者原文 `raw`，所以解析时把 `minute` 补成
18:00 / 10:00 完全幂等 —— 而下游因此**永远拿到两端有值的区间**，
不用每个消费方各记一遍保底常量。回归测试钉住「只写日期不会被写回成带时刻」。

**3. 周视图加了重叠分栏。** 设计没写。实测 `_demo` Day 1 的「晚餐（evening 模糊时段）」
把「17:30 小吃」整个盖住了 —— 确定的那件事反而看不见。照 Apple Calendar 摊成并排两栏。
顺带把泳道贪心收敛成 `lib/lanes.ts` 一份，月视图的住/行泳道共用它。

**4. `daySpan` 排除全天事件。** 一张全天周游券的名义窗口是 00:00–24:00，
算进跨度后周视图的轴被撑成整天，真正有事的十几个小时被压扁。
改在 `layout.ts` 源头排除，列表日头的「时间范围」也跟着变准了。

**5. 换乘点不需要 `dedupIds`。** 设计打算复用它给取/还车去重。实际上「带票面
时间轴」的事件（`transports.length > 0`）天然只有长途换乘 —— 取/还车是
`category: drive` 且没有 transport 块。少一层依赖。

**6. 预算口径抽进 `lib/budget.ts`。** 月格子右上角的当天预算必须和预算页
同一个数。原来 `build()` 私藏在 `BudgetView.tsx` 里，抄一份就会出现
「两个页面同一天不同数」。

**7. HashRouter 下不能用 `href="#事件id"`。** 整个 hash 就是路由，写页内锚点
会把地址栏改成一个不存在的路由。改成 `navigate('../list', { state: { focus } })`，
由列表页自己决定滚到哪 —— 进场定位的逻辑因此只有一处。

**8. 跨午夜的轴不钳位、改为拉长。** 设计写「方块钳到轴底、不把轴拉长」，
实现时改了主意：深夜场次被钳成贴底的一条线等于看不见，轴多画两小时代价很小
（时刻标签 `% 1440` 回卷显示）。单测钉的是拉长行为；租车底色的「列底」也随轴底走。

**9. 租车底色只有能力、没有 UI（按用户要求）。** 开关住在 `lib/settings.ts`
（`rentalBand`，默认关），渲染链路完整并有测试；首页设置面板做好之前
改 localStorage 的 `jjj:settings` 即可开。

**10. `mondayIndex` 收进 `@jjj/tripmd`。** `getUTCDay()` 是周日 = 0 的陷阱，
本来又要在 `calendar-grid.ts` 里手搓一遍 —— 正是这轮要收敛的那类重复。

顺带按「`components/` 只放 2 个以上视图共用的东西」把 `DayTimeline` /
`DayRail` / `TransportTimeline` / `ticket-parts` / `MapLinkButton`
搬进了 `features/itinerary/`（解开 `BudgetView → DayTimeline` 之后它们就只有列表在用）。

### 上线后按反馈的修改（2026-08-05）

| 反馈 | 改法 |
|---|---|
| 月视图宽度和别的界面对不齐 | `html { scrollbar-gutter: stable }`。短页面（月视图不滚动）与长页面（列表滚动）差出一整条滚动条宽度，切标签时整块内容横向跳一下 |
| 格子太挤 | 桌面端格子 104 → 156px，主题放宽（现为四行截断），并补上「N 项待订」角标 —— 全局唯一表示「你得做点什么」的数字。手机上主题/预算/待订本来就藏着，格子保持 96px，不然拉出一片空白 |
| 眉头要有周几 | `10/01 周四` |
| **通勤显示取消** | 与上面「通勤按真实时长画」那节相反。实际效果不好：一天二三十段路把每一列填成斑马纹，反而看不出空档在哪。路上耗时归列表的连接线 —— 那里有地点、方式和导航按钮 |
| 时间轴列盖住工具栏 | 时间轴列 `position: sticky` 自成层叠上下文，与工具栏同为 `z-20` 且 DOM 更靠后就赢了。压到 `z-10`（今天红线一并降到 `z-[1]`，仍在事件之上） |
| 格子还是挤；主题行忽高忽低 | 格子改 **1:2 纵横比**（`aspect-ratio`，跟着列宽自适应：桌面约 105×210，手机约 55×110，不再写死像素），内边距放松。长途换乘（航班/火车/轮渡）固定占一行、**空着也保留** —— 否则有换乘的格子会把主题往下推一截，一排格子扫过去主题忽高忽低 |
