# 地图视图设计 · 2026-08-11

五视图收官的最后一块。经 brainstorming 逐项确认，并用真实西雅图数据 + OpenFreeMap 真瓦片
搭过可交互 demo 验证交互参数（截图肉眼核过），本文记录拍板结果与理由。

## 背景

行程的空间形状——哪几天在城里扎堆、哪天进山跑远路、点与点彼此多远——是列表和日历
答不了的问题。地基早已埋好：地点表坐标 + 离群检测、`DAY_COLORS` 天数色环
（palette.ts 的注释写明是为「浅色底图上的路径线」调的）、`legs.geometry`
polyline 槽位（现全 null）、`gmaps_place_id`、`maplink.ts` 深链。

## 决策与理由

| 维度 | 决策 | 理由 |
|---|---|---|
| 渲染 | MapLibre GL JS | 矢量瓦片任意缩放清晰；免 key；静态托管零配置 |
| 瓦片 | OpenFreeMap（tiles.openfreemap.org） | 免 key、无限额、开源。OSM 官方瓦片明确禁止此类用途（2026-07 调研核实） |
| 底图样式 | **四选一：positron / bright / liberty / 3d，默认 bright**，选择持久化 | Harley 指定。3d = liberty + 建筑挤出层 + 俯仰角 |
| 路线 | v1 虚线直连（当天事件顺序） | FOSSGIS 路由 1 req/s 禁批量 → 真路网只能预计算进 `legs.geometry`，归下一轮 enrich 管道；运行时零 API 调用是硬约束 |
| 按天交互 | 页签 全程/D1…Dn + fitBounds；非选中天淡化（线 0.15 / pin 0.25） | demo 验证；「今天的路线在全局里的位置」比整页隐藏更有信息量 |
| 点 pin | 底部固定小卡（非 maplibre 气泡） | 390px 上气泡遮路径且要 React 桥接；底部卡稳定、复用现有卡片语言 |
| 天色 | 直接读 `day.color`（解析器已算好） | 单一来源；再调一遍 `dayColor` 就是下一对会漂移的口径 |
| 体积 | 五个视图路由**统一**懒加载 | 只给地图开懒加载是特例补丁；统一分包顺带把 react-markdown 移出主包 |

## 交互细节

- **页签**：`全程 / D1 / D2 / …`（现成 Segmented 组件）。切换即 fitBounds 到该范围
  （padding 让开页签高度）；默认全程——总览是最好的落地页，不持久化。
- **pin**：每天路径上的站点画天色圆点 + 白描边 + 当日序号。同一地点在一天内
  连续出现合并为一站；非连续重复（早出晚归回酒店）保留折返动线，pin 只标首次序号。
- **路径**：每天一条虚线，下垫白色描边线（casing）——bright/liberty 彩底会吞掉
  裸的彩色虚线，demo 里验证过。
- **底部小卡**：地点名 / 英文名 / Day N · 第几站 / 当天相关事件；「导航」走
  `maplink.ts`（Apple/Google 按平台偏好，地名 + 坐标双保险）；「在列表中查看」
  `navigate('../list', {state:{focus: eventId}})`——与周视图下钻同一机制。
  点地图空白关闭。
- **样式切换**：左下角四枚 chip（segChip 配方），写 `jjj:mapstyle`（readViewState 门面）。
  切样式后 MapLibre 会清掉自定义层，在 `styledata` 里重挂（demo 踩过的坑）。
- **缺坐标**：被引用但没坐标的地点（seattle 现为 7/30）在右下角 chip
  「N 个地点缺坐标」，点开列名字——同时是下一轮 Agent 补数据的工作清单。不静默消失。

## 边界与降级

- 有坐标地点 < 2 → 空态卡（States 组件），不初始化地图。
- 瓦片加载失败（断网/服务故障）→ 容器保持纸色 + 顶部警告条；pin 与路径**照常渲染**
  （GeoJSON 层不依赖瓦片）。
- 深色主题：地图 UI（页签/卡片/chip）走令牌自动切换；底图四种样式均为浅色，
  不硬造深色滤镜。OpenFreeMap 若日后提供官方深色样式，加第五个选项即可。

## 架构

```
lib/map-scene.ts        纯函数 + 单测：dayPaths / sceneBounds / missingCoords
features/map/MapView.tsx    地图实例、layer 管理、页签、样式切换（default export，懒加载）
features/map/PlaceCard.tsx  底部小卡
```

场景模型零依赖 maplibre——组件只画，公式可测，与日历的
`calendar-grid.ts`/`week-axis.ts` 同构。maplibre-gl 的 CSS 在 MapView 内 import，
随懒加载 chunk 走。

## 明确不做

- 真路网 polyline（下一轮 enrich 管道，槽位已留；填了之后虚线自动升级实线的逻辑也归那轮）
- marker 聚合（23 个点用不上）
- 地图上画住宿/租车区间（动线已含酒店/取还车点）
- 离线瓦片缓存
- 组件层测试基建（与全仓现状一致，lib 层单测 + Playwright 截图兜底）

## 验证

完整门（typecheck/test/data:check/build）+ 分包形状核对（maplibre 独立 chunk、
react-markdown 移出主包、index chunk 显著变小）+ Playwright 截图
（390px/桌面 × 深浅 × 全程/单天/弹卡/四样式/缺坐标 chip）+ 断网降级
（route.abort 瓦片域名，警告条出现且 pin/线仍在）。

## 实现记录

与设计一致落地，无功能删减。以下是实现期间的偏差与增补，均由核验发现。

### 环境与构建

- **dev 下地图整个画不出来**（画布空白 + 一个 404）：maplibre 的瓦片解析跑在 web worker 里，
  vite 的依赖预打包不带 worker 文件（`maplibre-gl-worker.mjs` 404）。`optimizeDeps.exclude`
  把它排除出预打包，浏览器直接吃 ESM。**只影响 dev，生产构建从一开始就是好的**——
  这类问题只有真跑起来才看得见，单测和 build 都是绿的。
- **容器定位必须写内联 style**：maplibre 的 CSS 随懒加载 chunk 在 Tailwind 之后注入，
  同特异性下后来者赢，类写法会被翻掉（容器高度塌 0、canvas 落回 300px 默认值）。
- 分包形状核对结果：`MapView` 965KB / gzip 254KB 独立 chunk（含 maplibre），
  react-markdown 落在 `derive` 共享 chunk，主包 `index` 不含二者。

### 390px 上暴露的三处遮挡（设计里没预见）

1. **底部 chip 压住 OSM 版权行**。版权归属不能压——实测版权行高 33px，
   两组 chip 抬到 `bottom-9`，`fitPadding` 底部同步 48 → 68。
2. **展开的缺坐标面板吃掉左下角样式 chip 的点击**。`items-end` 让容器盒子有最宽子元素
   那么宽（w-56），横跨到左下角上方；视觉上不挡，点击全被吞。容器 `pointer-events-none`，
   只在真正画出来的子元素上放行。**截图看不出来，是 hit-test 抓到的。**
3. **降级警告条压住日期页签和缩放按钮**（同 z-10、DOM 靠后就赢）。改 z-index 只是换个方向
   遮挡；警告条改为占自己一行，地图区域相应变矮，重叠在结构上不可能发生。
   maplibre 6 自带 `_resizeObserver`，高度变化自动重算，无需手动 `resize()`。

### 连带的头部改动（第五个页签的代价）

五个页签占满 287px，390px 手机上留给行程名只剩 **10px**——半个「西」字。四个页签时
还能显示「西雅图 5…」。经 Harley 拍板：`sm`(640px) 以下隐藏标题，把宽度整个让给页签；
640px 正是标题能完整展开的宽度（实测需 260px）。行程名在个人空间页刚点过，不丢上下文。

### 已知未解

- 样式 chip 的未选中态是 `segChip` 既有配色（#7a7263 on #f1e9d2 ≈ 3.8:1），
  低于 WCAG AA 4.5:1。这是全站 chip 的既有口径，不在地图这轮单独改。
- `3d` 在全程视野下看不出效果（俯仰有了，建筑挤出要拉近才可见）——符合设计，
  但「选了没反应」的观感真实存在，可考虑切 3d 时顺带 zoom in。

## 第二轮（2026-08-12）：抽屉式切换器 · 淡化真生效 · 点选居中

Harley 试用后提的三条。每条都牵出一个「看起来做了、其实没生效」的坑。

### 1. 左下角改成 Google Maps 式的抽屉

平时只占一枚 `▤ <当前样式>` 的 chip，点击向右滑出其余三个，选完立即收回。
四选一的语义没变（`3d` 仍与三个底图互斥），变的只是占地。

- 触发 chip **常驻最左且不参与滑出** —— 否则当前项会随选择在行内跳位置。
- 抽屉动效 = 外层 `max-width` 裁剪让出宽度 + 内层 `-translate-x-full → 0` 整体位移。
  只做 max-width 的话内容是「原地被揭开」，没有抽屉感；内层位移跑满整个时长，
  也顺带盖住了 max-width 提前到位后的那段空转。
- `overflow-hidden` 会连上下投影一起裁掉，靠 `-my-1.5` 配 `py-1.5` 撑出余量。

### 2. OSM 版权行不再占一行（推翻上一轮的 `bottom-9` 结论）

上一轮把两组 chip 抬到 `bottom-9` 让开 33px 的版权行，代价是底部白白空出一条。
实情是：`attributionControl: { compact: true }` 的 compact 形态**默认是展开的**
（390px 上实测 351×24，几乎占满宽度）。收成 ⓘ 之后底部整行还给地图，
两组 chip 落回 `bottom-2`，`fitPadding` 底部 68 → 48。归属没有丢，点 ⓘ 照常展开。

**时序是这里的全部难点**：建图那一刻属性列表还是空的（`maplibregl-attrib-empty`），
compact 态尚未建立，此时摘 `maplibregl-compact-show` 无效 —— 样式加载完拿到归属后
`_updateCompact` 会把 compact 与 compact-show 一起加回来。要等归属落定再摘
（`styledata` + 首个 `idle`）。之后它只在「刚进入 compact 态」时才加，故摘一次长期有效。

字号一并从 10.5px 提到 12px。代价是 390px 上展开态要占 250px，与右下角缺坐标 chip
挤不进同一行 —— 后者在抽屉展开时**整体淡出让位**（选完就收，让位是瞬时的；
多堆一行反而把刚省下的底部又占回去）。淡出必须连命中一起关，否则又是「看不见却能点」。

### 3. 非当天淡化其实一直没生效（真 bug）

`DIM_PIN` 早就写着，但 **maplibre 的 `Marker` 每次重绘都会用内部 `_opacity`
重写 `element.style.opacity`**（地形遮挡用的），硬写 style 会被切天时的 `fitBounds`
动画整个抹掉。改走 `marker.setOpacity()` 才落得下。`filter` 它不碰，可以直接写。

顺带把淡化压得更狠（线 0.15 → 0.07，pin 0.25 → 0.15）并叠一层 `grayscale(0.85)`：
选中某天后镜头会收到当天范围，别的日子多半已经飞出视野，只有边缘那几个还在画面里，
它们必须一眼就是背景。实测 D4 选中后 18 枚非当天 pin 为 `0.15 + grayscale(0.85)`、
7 枚当天为 `1 + none`。

### 4. 点选地点后居中

偏移量是布局数学，按铁律进 `lib/map-scene.ts` 的 `cardFocusOffset()` + 单测
（含负向对照：把 `/2` 去掉，两条断言立刻红）。小卡贴底通栏，可视区是「地图高减掉卡片」
那一块，让 pin 落在它的中心 = 相对视口中心上移 `(卡片高 + 间距) / 2`，
**只跟卡片高有关**；卡片过高时收敛到视口高的 30%，宁可偏下也不能把点顶出画面。
卡片高度随事件条数变，所以用 `useLayoutEffect` 等它渲染出来再量。

### 5. 小卡：序号徽章 + 换站（桌面按钮 / 手机滑动）

- **序号徽章**复用 `.map-pin` 那套外观，底色取当天动线色 —— 和刚点的那枚 pin 同色同形，
  「卡片说的就是我点的那个点」这件事不需要再读文字去确认。
- **卡片拆成两层**：外壳只管定位，内层才是视觉卡片。桌面端外壳带着 `sm:-translate-x-1/2`
  做水平居中，拖动位移若写在外壳上会把这个居中变换整个顶掉；写在内层就互不相干。
  左右翻页按钮挂在外壳上，所以不跟着拖动走，也因此能落在卡片外侧。
- **到头不循环**：`stopNeighbors` 返回 null，按钮置灰、滑动只弹回（那一侧还加了阻尼，
  让「到头了」在手感上能察觉）。循环会让「还有没有下一站」变得看不出来。
- 只在**当天之内**换站：序号是当日序号，跨天会突然跳回 1，语义就断了。

**手势判定不能挂在渲染时序上**（这轮踩的坑）：`onTouchEnd` 若去读 state 里的位移，
拿到的是本次渲染闭包里的值 —— 一串 touch 事件挤在同一个任务里时 React 还没重渲染，
读到的永远是 0，滑动永不触发。手势真值放 ref，state 只用来画。
真机上事件分散在不同任务里也许能碰对，但那是靠侥幸，合成事件一测就现形。

### 验证记录

完整门（typecheck / **16 suites 197 tests** / data:check 4 fixtures / build）全绿，
MapView 仍是独立 chunk（gzip 254.75KB）。截图覆盖 390px × {收起, 展开, 选完收回,
全程, D4 淡化, 弹卡居中, 深色展开} + 1280px × {展开, 弹卡居中}。

三处不能靠肉眼的都用脚本量了：展开态切换器右边缘 250.6 vs 缺坐标 chip 左边缘 233.6
（确认重叠 → 才有淡出让位这一条）；淡出后原位置 `elementFromPoint` 返回 CANVAS
（没有透明区吃点击）；点选后 pin 从 y=562 移到 356，与 `cardFocusOffset` 的理论值
366 吻合（pin 中心 367）。

换站用合成 TouchEvent 真滑了一遍：左滑 1→2→3、右滑回 2、退到第 1 站再右滑原地不动、
短滑 30px 不换站（阈值 56）；桌面按钮 1→2→…→7，首末两端各自置灰；
按钮位置 hit-test 命中自己，卡片左缘外 6px 命中地图（外壳的透明区没吃点击）。
