# 作者提示词

把下面分隔线之间的**全部内容**粘给 Claude / GPT / Gemini，末尾附上你的行程需求。

产出存成 `apps/web/public/data/<trip-id>/plan.md`，然后 `pnpm data:check`。

---

你要写一份 **TripMD** 格式的旅行计划。这是一种既能给人读、又能被程序确定性解析的 Markdown。

## 铁律

1. **每个 `###` 事件下面必须紧跟一个 ` ```trip-event ` 块。** 漏一个就解析失败。
2. **事件的 `time` 是「到达该地点、开始活动」的时刻，不是出发时刻。** 路上耗时由**上一个事件**的 `to_next` 承担，所以上一个事件必须**提前 travel 分钟结束**。这是最容易写错的地方。
3. **坐标不确定就别写。** 瞎编的经纬度比没有坐标糟得多。只给你确信的知名地标写坐标；餐厅、民宿、小众观景台一律留空。
4. **同一地点全文用完全一致的名称。**
5. 机器字段只放在 ` ```trip-* ` 块里；块外的正文写给人看，随便用粗体、列表、⚠️、表格。

## `trip-event` 字段

| 字段 | 必需 | 值 |
|---|:--:|---|
| `time` | ✓ | `18:25–18:55` / `"13:11"`（点，时长为 0，**要加引号**）/ `morning`·`afternoon`·`evening`·`night`·`allday` |
| `category` | ✓ | 见下表 |
| `place` | | 地点名，须与地点表完全一致 |
| `flags` | | `[warning, tentative, optional, needs-booking]` |
| `cost` | | 自由文本，如 `约 $70/人`、`$49 × 2 = $98`、`$250–400`。程序自动抽金额做预算，写清 `/人` 还是总额；可有可无的加「（可选）」。**预算统计只认这个字段** —— transport 的 `price` 是票面展示，机票钱要进预算就把合计写到 `cost` |
| `booking` | | `{status: required, deadline: 2026-08-01, note: 需提前订位}` |
| `stay` | | **入住事件必写**：`{platform: 万豪/希尔顿/Airbnb…, stars: 4, room: 大床房, parking: 含/不含, breakfast: 含/不含}`。**不知道的字段直接省略、绝不编造** —— UI 会留「待填」空位 |
| `notes` | | **注意条目**，字符串列表。截止、防盗、必带装备、营业时间坑…… 一条一个坑，UI 渲染成红色「注意」条目行。有坑写这里，不要埋在正文里 |
| `transport` | | **抵达/离开/多目的地间的长途移动必写**（不限飞机）：`{traveler: 谁的（多人汇合时）, mode: flight/rail/hsr/drive/ferry/bus, carrier: 承运方, number: 班次号, from, to, dep_time: "10:15", arr_time: "13:11", duration: 11h55m（全程含中转）, cabin: 经济舱/指定席, baggage, through_check: 中转行李是否直挂, refund: 退改签政策, price: 票价如 $189, stops: [{airport: ICN, arr_time: "13:55", dep_time: "16:05", leg: 前一段行进时长, wait: 2h10m, dep_airport: 异地换乘的再出发点}]}`。**多人从不同地方出发汇合时写成列表，一人一条**。**不知道的字段直接省略、绝不编造** —— UI 会留「待填」空位（含票价的「预算」槽） |

| `to_next` | | `{mode, minutes, km, label, note}` |

**只写时刻，不用管日期。** 出发日、中转到发日、到达日都由工具沿时间轴推出来，跨天自动补红色 `+n` 角标。两个例外必须手写，因为跨时区推不出来：**跨日期变更线的航班写 `arr_day_offset: 1`**（或直接照票面写 `arr_date`）；**抵达型事件的航班其实前一天起飞时写 `dep_date`**。中转停留只要写了 `wait`，哪怕停 27 小时日期也能算对。

**类别**（只能用这些，五族十八类）：

**玩**：`sight` 景点 · `outdoor` 户外（徒步/公园/湖）· `viewpoint` 观景（观景台/日落机位/**风景自驾路段**）· `experience` 体验（需买票：缆车/游船/观光飞行）。**吃**：`food` 餐厅（正餐/市场）· `cafe` 咖啡 · `snack` 小吃甜点 · `bar` 酒吧。**住**：`hotel` 酒店 · `homestay` 民宿（Airbnb/木屋/町屋）。**行**：`flight` 航班 · `rail` 火车 · `hsr` 高铁（新干线）· `ferry` 航运 · `drive` 自驾（含提还车）· `bus` 巴士 · `transit` 长程通勤。**事务**：`logistics`（补货/寄存/装车/进航站楼）

**「行」只收长途。** 市内地铁/公交/打车这类短途通勤**不要单独成事件**，写进上一个事件的 `to_next`。一段乘车本身就是体验的（观景列车、看日落的渡轮），按「玩」分类。

**起床/洗漱/收拾这类日常动作不要成事件。** 事件是「值得在时间轴上占一格的事」；早晨的准备写进当天导语一句话即可。退房只有携带行李寄存、装车这类实际动作时才值得成卡。

**11 种交通方式**（`to_next.mode` / `transport.mode` 用，与类别是两套枚举）：`walk` `drive` `rideshare` `rail` `hsr` `bus` `monorail` `streetcar` `ferry` `flight` `bike`

**4 种状态标记**：
- `warning` 有坑（具体的坑写进 `notes`）
- `tentative` 还没定下来（标题旁「待定」角标）
- `optional` 赶不上可以砍（卡片左边条变虚线，不写文字）
- `needs-booking` 出发前必须预订

## 时间衔接（最容易错，请逐条检查）

```yaml
### 苏扎罗图书馆
time: 15:15–16:03          # ← 16:03 结束，给后面留 12 分钟车程
to_next: {mode: drive, minutes: 12}

### 煤气厂公园
time: 16:15–17:30          # ← 16:15 到达。16:03 + 12 = 16:15 ✓
```

写完每一天，从头核对一遍：**上一个事件的结束时间 + `to_next.minutes` ≤ 下一个事件的开始时间。**

两个特殊情况：

- **事件本身就是移动**（风景自驾、坐轻轨这个动作）→ 把时长写进事件的 `time`，`to_next` 就别再给 `minutes`
- **当天最后一个事件不要写 `to_next`**（没有下一个事件了）。如果要表达"然后去机场"，就把机场作为一个真实事件写出来

## 写好这份计划

结构对了只是能解析。**真正有价值的行程在正文和变体里：**

- **首段是摘要。** 正文第一段（第一个空行前）常显在卡片上，其余折叠。第一段一句话说清最关键的事。
- **抵达和离开要作为第一天第一个、最后一天最后一个事件写出来**，带 `transport` 块（飞机/火车/自驾/轮渡都用它）。多目的地行程中间的长途移动同样写成事件 + `transport`。
- **多人从不同地方汇合**：一个事件里 `transport` 写成列表，每条带 `traveler` 标签，例如她从 PVG 直飞、我从 SNA 飞。
- **正文写「为什么」，不只是「是什么」。** 不是"去 Kerry Park 看日落"，而是"18:15–18:50 金光转粉紫，18:50–19:15 蓝调时刻更出片；山上路边位极少，早到 15 分钟绕圈"。
- **变体（`#### 变体 · 条件`）是这个格式最重要的特性。** 凡是"如果 X 就改成 Y"的判断——天气、排队、季节性关闭、班次取消——都写成变体。这是一份计划最值钱的部分。
- **赶不上时的砍站顺序写进当天导语**（「落后了就按 X → Y → Z 的顺序往下砍」），不要另开字段或在一天末尾单列小块 —— 每天以卡片收尾。
- **硬约束写足 `note`。** 尤其是倒推链：为什么必须 11:20 还车。
- **坑写进 `notes` 条目，不要埋在正文。** 每条一个坑、说明理由（"必须自带午餐：Paradise 以外整条线没有吃饭的地方"）。正文留给「这是什么、为什么值得」。
- **简要介绍（首段）不写通勤** —— 怎么去是上一个事件 `to_next` 的事。
- 备选方案（第二第三选择的餐厅、住宿）写进正文或附录，不要另开事件。

## 租车（有的话）

行程里有租车/长租设备时，加一个 `trip-rentals` 块（任意 `##` 标题下）：

```trip-rentals
- what: 保时捷 Macan
  platform: Turo                # 租车平台/租车行
  from: "2026-10-02 11:30"
  to: "2026-10-05 11:20"
  pickup: 唐人街提车点
  dropoff: 唐人街提车点          # 与 pickup 不同即异地还车
  mileage: 600 英里              # 里程上限（不是预估行驶里程）
  insurance: 全险 + 免赔额 0     # 保险方案
  refund: 取车前 24 小时免费取消  # 退改政策
```

除 `what`/`from`/`to` 外不知道就省略（UI 留「待填」空位）。**坑不写进这里** —— 「必须 11:20 后提车才落进 3 天计费」这类提醒写进提车事件的 `notes`。

提车/还车的动作照常写成当天的 `drive` 事件（地点用取车点），费用写在提车事件的 cost 上 —— 取车卡上会自动长出租期模块。

## 附录

不属于任何一天、但不能丢的内容单独开附录。常见的：`## 附录 · 预算`、`## 附录 · 打包清单`、`## 附录 · 出发前必办`、`## 附录 · 雨天预案`、`## 附录 · 住宿备选`。

每个附录紧跟一个 ` ```trip-ref ` 块声明 `id` 和 `icon`（emoji），其后是自由 Markdown。附录内的小标题用 `###` 或更深（`##` 会被当成新分区）。
